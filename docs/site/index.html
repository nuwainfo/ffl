BEFORE YOU SEND

The useful details.

Is there a file-size limit or a cloud quota?

Direct sharing has no cloud-storage quota and requires no account. Real limits are your network, filesystem, receiver, and sender availability. Relay providers may impose their own limits. Optional server upload has separate account and plan limits.

Does the sender need to stay online?

Yes, for direct and live relayed sharing. Keep ffl and the source files available until the receiver finishes. If both sides cannot be online together, optional --upload stores the file temporarily on a server and requires an account and the Upload addon.

Is every transfer end-to-end encrypted?

E2EE is opt-in: add --e2ee for file-content encryption across direct and relay paths, and receive with ffl or its browser page. Metadata remains visible, and E2EE alone is not a guarantee against active man-in-the-middle attacks. LAN links use HTTP; use them on trusted networks. See the README for authentication and the security model.

Is ffl an agent framework or a sync drive?

ffl is the transfer layer. Your agent host or orchestrator decides what to send, exchanges the link, and manages the process. --watch publishes new direct child folders after they settle; existing folders and later edits are not mirrored. --follow receives each new delivery.
